## Phase 1：可运行工程基线

目标：建立可启动、可迁移、可测试的技术骨架，重量仍为人工录入。

- 初始化 Python 项目、FastAPI 应用、配置加载、健康检查和结构化日志。
- 初始化 SQLAlchemy 2.x 会话及 Alembic；首版迁移严格落实 Phase 0.1 字段与约束。
- 初始化 Vue 3 + TypeScript + Vite + Element Plus、基础布局和 API 客户端。
- 增加后端/前端 Dockerfile 和 Compose 服务。
- 配置 pytest、类型检查、lint/format、前端检查和 GitHub Actions。
- 为 `Decimal` 吨位计算和状态机建立不依赖数据库的测试基线。

退出标准：新开发者可按 README 启动完整技术骨架；迁移可升级/回退；CI 通过。Phase 1 不接真实地磅设备。

## Phase 2：身份、车辆与人工称重 V1

- 用户认证、密码安全和 RBAC 权限矩阵。
- 车辆、客户基础管理；车辆核定总质量不得硬编码。
- 创建独立称重任务，货物类型使用固定枚举和前端下拉框。
- 实现 `WAIT_TARE → TARE_COMPLETED → LOADING → WAIT_GROSS → GROSS_COMPLETED → COMPLETED` 状态机。
- 实现 `PENDING / NORMAL / OVERWEIGHT` 独立结果和超重强制复磅。
- 实现追加式 `WeighingRecord`、车辆限重/司机快照、任务取消和磅单历史。
- 实现并发控制、幂等请求与 `AuditLog`。
- 前端实现创建任务、首次称重、第二次称重、复磅与历史页面。

退出标准：无订单任务可完整称重；超重无法完成；全部复磅读数永久保留；核心边界和非法跳转有 pytest 覆盖。Phase 2 仍只实现 `MANUAL` 来源。

## Phase 3：订单与库存

- 物料、订单、订单明细、库存余额和库存流水。
- 称重任务可选关联客户与内部订单，但不自动履约或记账。
- 增加显式“确认业务入/出库”用例，人工确认物料、单位、数量和称重依据。
- 实现库存冲正、订单履约调整、幂等与跨模块集成测试。
- 明确混装、多单位和容差策略后再实现对应模型。

退出标准：单纯过磅不产生库存副作用；显式记账可追溯到称重任务并可安全冲正。

## Phase 4：磅房工程增强

- 抽象并验证 `WeighbridgeAdapter` 接口。
- 增加 `MockWeighbridgeAdapter` 支持自动化与演示。
- 在明确设备型号后评估 Serial、RS-232/RS-485、Modbus 或厂商协议适配器。
- 设计稳定值判定、设备断连、超时、重复读数和 kg→t 转换测试。
- 增加可打印磅单、作废/重开与更正流程。

退出标准：设备输入与人工输入复用同一领域规则，设备异常不会破坏任务状态或历史记录。

## Phase 5：作品集与生产准备

- 演示数据脚本（仅开发环境）和端到端测试。
- OpenAPI、架构决策记录、截图、部署与运维指南。
- 数据库备份恢复、结构化日志、监控与安全检查。
- 称重任务列表、历史统计和并发提交性能验证。
- 补充许可证和贡献指南。

## 未来阶段：AI / Agent / MCP（当前不实施）

待核心业务、权限和审计稳定后，评估只读查询用例：

- `query_weighing_task`
- `query_weighing_history`
- `query_today_weighing_records`
- `query_overweight_records`
- `get_today_total_net_weight`
- `query_vehicle_history`

候选问题包括“今天煤炭共称多少吨”“今天是否有超重车辆”“某车近一个月来厂次数”。是否使用模型 API、RAG、MCP 或 Agent 编排必须由明确收益、安全与权限需求决定。

## Phase 1 前仍需人工确认

以下问题中，前四项会影响首版迁移或核心枚举，应优先确认：

1. `cargo_name` 在 `cargo_type=OTHER` 时是强制必填还是仅建议填写。
2. 任务取消允许到哪些状态；已经产生正常/超重毛重后能否取消，以及谁有权限。
3. 称重记录录错时的 V1 更正模型：追加 `CORRECTION` 类型、作废标记，还是整单作废重开。
4. 磅单编号规则、是否允许重打、作废与重开是否需要单独编号。
5. 客户和订单同时选择时，是否必须严格一致；订单关联是否仅限 `TIMBER`。
6. 是否允许同一任务更换车辆或司机；建议皮重后禁止更换车辆。
7. 车牌、司机手机号、车辆类型的具体校验规则和车辆停用策略。
8. 超重卸货后再次进入 `WAIT_GROSS` 的操作权限及是否必须填写处置备注。
9. V1 是否需要保存人工录入的实际称重时间，还是只采用服务端记录时间。
10. 多工厂、多磅、班次交接、时区和任务编号规则。
11. 后续内部库存的单位、混装物料、订单容差和负库存策略（不阻塞独立磅房 V1）。
12. 真实地磅型号、通信协议、稳定值规则与断网要求（不阻塞人工录入 V1）。
